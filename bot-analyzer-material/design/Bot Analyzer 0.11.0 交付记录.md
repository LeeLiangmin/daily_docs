## 这一版做了什么

1. 字号：侧栏正文随 VS Code 界面字号加 1（默认 13 即 14），次要文字比正文小 2 且不小于 12（默认 12），没有更小的；行高为正文加 12（默认 26）。规则说明面板同一套。
2. 质量目标：名称行只写名称、缩写和值，「目标 ≤ 300」换到名称下面一行（12，次要色）。
3. 状态栏提示：去掉「打开整个项目」「打开当前文件」；操作行只剩重新检测、导出报告、查看输出日志（当前文件没有查看输出日志）。点击状态栏与读屏标签不变。
4. 行号写法对齐 VS Code 状态栏：单行「行 500」，范围「行 548–685」，带列「行 5，列 3」，悬停位置「行 548–685，共 138 行」；跨文件「dir.rs:548–685」；配置错误「bot-metric.toml:2」。
5. 最小宽度仍是 280（试过 300，见「验证」）。

## 验证

- 自动测试 102 项、端到端 11 项（真实 bot-metric 1.2.3 分析 ripgrep）全部通过。
- 真实界面（深色、浅色）：脚本读取计算后的样式，侧栏正文 14px、质量目标第二行 12px、键值行高 26px，小于 12px 的元素 0 个；规则说明面板同样。状态栏提示、悬停「行 548–685，共 138 行」都按新写法。
- 实测发现的问题：最小宽度 300 在默认侧栏宽度（300）下会出横向滚动条，值被挡住（要扣竖向滚动条），已改回 280。
- 这一版没有再做独立代码评审，没有在 Windows 实机上运行过。

## 与画布的差别

- 画布不扣滚动条，「300px 默认宽度」一栏看不出上面那个问题；画布里最小宽度的文字已改为 280 并写明原因。
- 度量里「高圈复杂度函数占比(HCFR)」「高修正圈复杂度函数占比(HMCR)」在 300px 宽会被省略（悬停写全，约 340px 以上显示全）。

## 已知限制

- 字号跟 VS Code 界面字号，不跟编辑器字号。
- 「行 5，列 3」按英文界面「Ln 5, Col 3」的中文说法写，简体中文版状态栏的确切字样没有核实；范围写法「548–685」是惯例，VS Code 没有范围写法。
- 没有在 Windows 实机上运行过，建议先试装；Windows 包不带 bot-metric.exe。
- 随标记发给客户端的 items 和客户端的 Marks.inItem 已没有用处，留待下一版清理。
