# 信息密度指南

## 0. 先说清楚“密度”是什么

密度 = 单页内**可被验证的具体信息量**，不是字数，也不是元素数量。
- 高密度：`cargo check` 跳过 LLVM 与链接，所以比 `cargo build` 快；命令、原因、对比都在一句里。
- 低密度：“cargo check：更快。”（结论无依据）
- 假高密度：一整段没有结构的文字，或塞满装饰性的图标与色块。

## 1. 为什么会做空（诊断）

| 症状 | 根因 | 修法 |
|---|---|---|
| 每页 3–4 张卡片，每张一句话 | 先选了版式再找内容 | 先写证据清单，再选版式 |
| 只有话题词标题、没有结论 | 没有论点 | 标题保持短（“依赖解析”），把结论写进副标题 `.lede`（“按主版本兼容范围解析，结果锁进 Cargo.lock”） |
| 只有名词，没有“怎么做” | 停留在概念层 | 补命令、参数、输出、例子 |
| 页面下三分之一空着 | 套用了 70% 填充规则 | tech / read 档填充 80–95%，多出来的空间放证据 |
| 列表被硬改成卡片 | 误用“少用 bullet” | 并列的、有共同属性的，用表格；有顺序的，用步骤序列 |
| 图只有方框加箭头 | 图没承载信息 | 每个节点加：做什么、产物、观察方式 |

## 2. 提高密度的十种手法（按性价比）

1. **标题 + 结论 + 证据**三段结构：短标题，副标题一句结论，中间 2–4 个证据块，页底可选一条“所以”。
2. **表格替代散文**：对比、参数、选型，一张表比三段话省一半篇幅，还能比对。
3. **带批注的代码**：左边代码（8–14 行），右边按编号逐条解释，每条一行，含“为什么”。
4. **图上标注**：节点里放名称、职责、产物；边上标数据或命令；图下方放一行观察命令。
5. **每个概念配一个最小例子**：输入、输出、错误信息原文。
6. **数字化**：默认值、阈值、复杂度、耗时量级、版本号，能量化就量化。
7. **写取舍**：A 的好处、A 的代价、什么时候选 B。没有代价的方案是没讲完。
8. **写坑**：常见误用、报错、失效条件，页底一条“注意”。
9. **两栏或三栏并排**：宽屏放得下，别只用左半屏，右半屏留空。
10. **分层字号**：论点 36–44px，证据 24–28px，图表内标注 22px 起（tech / read 档）。

## 3. 删除测试（每页都过一遍）

- 删掉这页，观众会**丢失哪一条具体信息**？答不出来 → 页太空，补内容或合并。
- 只看这一页，能不能**独立带走一个可执行的东西**（命令、规则、判断标准）？
- 有没有一句话是任何主题都能套用的空话（“提升效率”“更加灵活”）？有就删或换成具体的。
- 有没有信息只存在于备注里、页面上没有？关键结论要上屏，备注只放展开。

## 4. 前后对比示例

**前（稀）**：标题“编译流水线”，无结论；6 个盒子，每个盒子一个缩写加两字（“AST 语法分析”）。

**后（密）**：标题仍是“编译流水线”，副标题“五种中间表示，Rust 特有的检查集中在前三种”，再加每个阶段的职责、产物和观察命令。
- 证据块 1：6 列流水线；每列 = 表示名称、做什么、关键检查（如：类型推断、借用检查）。
- 证据块 2：一行“怎么亲眼看到”的命令表：
  `rustc -Zunpretty=expanded`（宏展开，需 nightly）、`--emit=mir`、`--emit=llvm-ir`、`--emit=asm`。
- 页底：借用错误在 MIR 阶段报出，此时还没有生成任何机器码；所以 `cargo check` 能提前发现，且比完整构建快。

## 5. 密度与可读性并存

- 结构一致：同类页面用同一栅格，观众学会一次就能快速扫读。
- 层级清楚：标题最大，证据块次之；用字重与颜色标出关键词，别加更多字号。
- 留白放在块与块之间，而不是留一大片空区。tech 档的间隙 24–32px，块内边距 24–32px。
- 一页超过约 260 词（tech）时拆页；拆的方式是拆论点，不是删证据。
- 相邻页保持“论点连续”：上一页的副标题结论，就是下一页的前提。

## 6. 不同页型的最低配置（tech 档）

| 页型 | 最低配置 |
|---|---|
| 概念页 | 定义一句 + 图或对比表 + 例子 + 一条常见误解 |
| 机制页 | 流程图（节点带产物）+ 观察命令 + 关键不变量 |
| 命令 / API 页 | 用法表 + 一段可运行示例 + 输出 + 常见报错 |
| 选型 / 对比页 | 对比表（≥ 4 个维度）+ 适用场景 + 代价 |
| 总结页 | 3–5 条结论，每条附依据或数字 + 下一步行动清单 |

## 7. 密度不是越高越好：节奏与用途

- 每页都在词数上限，等于没有重点；最高密度页不超过六成，其余用中低密度页和锚点页调节。
- 先定用途：现场讲的稿子，屏幕词数要低于会后读的稿子。同一份内容想两者兼顾，就做屏幕版和讲义版。
- 假密度会拉高词数却没有信息：整列相同的表格列、复述标题或副标题的结论条、重复三处的同一句结论。
- 脚本能抓的（词数、块数、常量列、结论条重合）见 `scripts/check_deck.py`；抓不到的（对不对、是否矛盾）见 `quality-gates.md`。
