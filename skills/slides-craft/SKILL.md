# slides-craft：通用幻灯片制作 skill（v4）

## 文件一览

| 文件 | 用途 |
|---|---|
| `references/density.md` | 信息密度：档位、提高密度的手法、删除测试 |
| `references/aesthetics.md` | **短标题写法**、间距与对齐、层级、块样式、版面自查 |
| `references/design-rules.md` | 配色、字阶、版式、交付前清单 |
| `references/layout-recipes.md` | 版式配方（基于外壳组件类）、锚点页 |
| `references/quality-gates.md` | 内容门禁：事实表、一致性、可推导、承诺映射、节奏 |
| `references/html-viewer.md` | HTML 查看器：居中缩放的正确做法与验证 |
| `references/output-targets.md` | 输出形式选择与交付说明 |
| `assets/deck-shell.html` | 单文件 HTML 外壳：主题令牌、组件类、自动页码、页面内置自检 |
| `assets/layouts-gallery.html` | 11 页版式图库（封面、目录、表格、流程、代码、对比、大数字、步骤、卡片、总结、结束），复制页面改内容 |
| `scripts/check_deck.py` | 标题长度、密度、对比度、节奏、模板的静态检查（仅标准库） |
| `scripts/optional/test_viewer.py` | 可选：有 playwright 时的多窗口实测；没有也不影响交付 |


目标：信息充实、准确、自洽，又不显拥挤。三条底线：
- **不能空**：看完一页，能带走具体的名称、数字、机制、命令或取舍。
- **不能错**：数字能复算，前后不矛盾，承诺有交付。
- **不能单调**：整套有起伏，不是每页同一个模板。

脚本只能检查“多不多、齐不齐、单不单调”，通过不等于内容正确；内容门禁要人工过（`references/quality-gates.md`）。

## 工作流（按顺序）

1. **澄清简报**（能推断就不要问）：受众、场合、时长、有无品牌规范。信息不足时写一行假设直接开始；缺失的数字和名称用 `[待补]`，不要编造。
2. **定用途和密度档位**
   - 先定用途：**现场讲** 还是 **会后读**，或两者都要（做屏幕版 + 讲义版）。
   - 再定档位（见 `references/density.md`）：

     | 档位 | 场景 | 每页文字量 | 最小字号（1920 画布） | 内容区填充 |
     |---|---|---|---|---|
     | talk | 大屏、多人、现场讲 | 30–100 词 | 24px | 60–75% |
     | tech（专业受众默认） | 工程师分享、评审、培训 | 100–260 词 | 22px | 80–95% |
     | read | 会后传阅、汇报材料 | 150–380 词 | 20px | 85–95% |

3. **建事实表**：全套反复出现的概念定义、数值（含单位和推导）、章节结构、对外承诺（“听完你能……”），见 `references/quality-gates.md` §1。
4. **定视觉方向**（`references/design-rules.md`）：字体、配色、字阶、深浅交替。
5. **写内容大纲**：每页写出「短标题」「结论（一句，放副标题）」「证据清单（要放进去的具体东西）」。证据清单为空的页不成立。同时规划节奏：标出 2–3 页低密度锚点页。
6. **逐页写作**（`references/layout-recipes.md`、`references/aesthetics.md`）：从版式图库复制最接近的页；短标题 + 副标题；证据分成 2–4 个结构化块；有新信息才加结论条。
7. **门禁**（`references/quality-gates.md`）：
   - 内容门与一致性门：对照事实表逐页核对；数字必须能在页上推出。
   - 跑脚本：`python3 scripts/check_deck.py <目录> --profile tech`，处理所有问题，再看“人工核对”清单。
   - 承诺到交付：目录里每条“听完你能……”都要有对应页。
   - **输出 HTML 时**：用 `assets/deck-shell.html` 起手（版面参考 `layouts-gallery.html`），只增删 `<section class="slide">`。**验证不需要任何浏览器自动化**：静态脚本 + 页面内置自检（在浏览器里按 C，或网址加 `?check`，或控制台调用 `slidesCheck()`）。没有浏览器可用时，`check_deck.py` 加人工自查清单（`aesthetics.md` §6）即可交付，并在回复里说明未做渲染检查。
8. **交付**：说明做了什么；列出占位符、易变事实和需核实事项；提示怎么继续改。

## 每页内容预算（tech / read 档）

1. 短标题（≤ 18 个汉字等效，无逗号）+ 结论副标题（≤ 40 字，单行）
2. 至少 2 个结构化证据块（表格、带批注的代码、示意图、对比栏、步骤序列）
3. 至少 3 类具体信息：名称 / 命令 / API；数字 / 版本 / 阈值；机制或因果；对比与取舍；例子；坑与反例
4. 结论条**可选**：只在有新信息时用（含义、反例、阈值、行动），不复述标题
5. 演讲者备注：展开、口头解释、可能的追问

## 硬规则

- **数字可推导**：比值、加速比、占比、CPI、成本，页上写出输入 → 公式 → 结果；无参数的“约 1.3”不允许。
- **前后一致**：同一概念的措辞、同一个量的数值和结论全套统一；小结必须与正文一致。
- **标题短、结论在副标题**：标题写主题（名词短语），不写完整句子；结论放 `.lede`。副标题里的限定词（总是、只要、连续、按……排序）都要有依据。
- **承诺必有交付**：目录里的每条“听完你能……”落在具体一页。
- **不允许空洞页与假密度**：只有名词短语加一句话的卡片页、整列相同的表格列、复述标题的结论条，都算未完成。
- **节奏**：最高密度页不超过六成；每 4–5 页一张锚点页；版式至少 3 种。
- **SVG 一比一**：viewBox 宽度等于显示宽度；图内字号不低于该档最小值。
- **HTML 外壳不手写**：必须 `box-sizing:border-box`，缩放用 `transform-origin:0 0` 加平移居中；不得用 grid 居中配 `transform-origin:center`。颜色一律用主题令牌，不在页里另写十六进制。
- 对比度：正文 ≥ 4.5:1，大字（≥ 44px）≥ 3:1；不用纯白纯黑；颜色不单独传达含义。
- 页脚位置固定，其他内容不进入底部安全区；卡片里字占不到一半高度就放大字（`.lg`）或不拉伸（`.fit`）。间距只用 8 的倍数。
- 不编造统计数字、引语、来源；易变事实在备注里写来源或标“需核实”。

## 中文与技术类内容补充

- 中文字体默认 Noto Sans SC；代码 / 命令 / 路径用等宽字体。
- CJK 按字宽估算：汉字 ≈ 1 × 字号，拉丁字符 ≈ 0.55–0.6 × 字号。
- 代码块：深色底、等宽、8–14 行、行长 ≤ 60 字符，配编号批注；不依赖缩进。
- 命令必须真实可运行；示意值与实测值要在页面上区分。
