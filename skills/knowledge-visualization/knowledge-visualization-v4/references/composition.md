# Composition

## One main visual

The spine occupies most of the canvas (≥ 80% for mechanism targets). The title states the traceable question. There is no footer recap.

## Primary path patterns

```text
START → CORE → RESULT
CAUSE → MECHANISM → EFFECT
```

For multi-actor mechanisms, prefer lanes over a single row:

```text
            time ───────────────────────────▶
Actor A     ███  ███  ███ ░░░░ ███ ███
               ↓    ↓    ↓        ↑   ↑
Actor B        ═══════════════════╯   │
                    ═══════════════════╯
```

## Secondary information

Attach it to the spine element it modifies with a leader line, bracket, or placement inside the same lane. Numbered callout markers may sit on the spine; the numbered text sits next to them. No standalone panels.

## Density

If crowded:

1. remove content that serves another target
2. remove secondary detail that does not aid reconstruction
3. group related elements
4. shorten labels
5. split into a second image

Do not simply shrink everything.

## Title and legend

- Title = the question. Optional subtitle = the scenario ("3 requests, 1 JS thread").
- Legend only for encodings that are not self-evident (arrow styles, hatch = idle). Keep it small and at an edge.
