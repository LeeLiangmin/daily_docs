# Visual Narrative

Visual Narrative is the path the viewer's attention should follow — the bridge between the knowledge model and the viewer.

## Narrative patterns

- **Mechanism** — input → mechanism → output
- **Execution** — action → A → B → C → result
- **Causal** — condition → behavior → intermediate effect → outcome → feedback
- **State** — state → event → state → event → state
- **Comparison** — question → dimensions → alternatives → meaning of differences
- **Historical** — context → event → consequence → later change
- **Spatial** — location → relationship → distribution/movement → effect
- **Structural** — whole → major parts → critical relationships (only when §0 found nothing to trace)

## The spine

For Mechanism / Execution / Causal / State narratives, the narrative collapses to **one spine**: the path of the traced object.

Test: can you draw the narrative as one continuous line (possibly looping, possibly crossing lanes) without lifting the pen? If you need separate strokes for "architecture", "phases" and "queues", you have several narratives. Pick one; defer the rest.

## Narrative vs. visual structure

Narrative:

> The viewer should follow **three requests through one JS thread** to understand **why nobody is blocked while I/O is pending**.

Visual structure then says what must be visible (axes, lanes, crossings). Do not skip this translation: a good narrative can still become a poor image if its relationships are not made spatially explicit.

## Narrative test

> The viewer should follow ______ to understand ______.
> The viewer must visually perceive ______ between ______ and ______ because ______.

If either is vague, do not start visual styling.
