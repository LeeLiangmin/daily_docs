# Agent Skill 精简与重写研究综述

## 摘要

Agent Skill 将工作流程、工具用法、领域规则和验证要求组织成可复用的指令。随着模型能力提升和 skill 持续积累，部分内容可能变得重复，部分流程可能增加不必要的工作，而精确参数、操作方法和业务约束仍有价值。围绕这一问题，现有研究形成了结构化精简、按需加载、成本感知重写和执行反馈驱动修订等路线。

这些研究共同说明，skill 优化需要同时考虑信息内容、组织方式和执行效果。文本缩短不必然降低任务成本，模型重写也不必然破坏能力；结果取决于保留了什么信息、如何使用执行反馈，以及评测覆盖了哪些行为。较有依据的方向是：以任务质量为约束，根据内容作用选择修改方法，通过实际执行比较收益，并将长度与运行成本分别衡量。

## 1. Skill 的价值与负担

### 1.1 内容丰富不等于任务收益高

Skill 同时包含多种性质不同的信息：决定何时使用的描述、直接控制执行的规则，以及帮助理解或操作的背景、示例和模板。将这些内容全部放入正文，容易使每次任务承担相同的上下文负担，即使其中只有少量内容与当前请求有关。

SkillReducer 对 55,315 份公开 skill 进行了调查，报告了描述缺失、正文混杂和引用材料加载过多等问题。[1] 这支持对 skill 进行结构整理，但不能把背景、示例和模板一概视为无用内容。示例有时也是规范：输出字段、边界条件和调用顺序可能只出现在示例中，删除示例就可能删除唯一的行为依据。

模型升级为重新评估提供了理由，却不能直接证明某条指令过时。模型可能已经掌握通用概念，仍不知道具体环境的工具契约。同一段提示在不同模型、任务或运行器下，也可能产生不同效果。

### 1.2 看似相关的指令也可能导致失败

Dong 等通过比较完成同一任务的有 skill、无 skill 或语义匹配的参考运行，分析 skill 引入的功能失败与效率退化。研究收集了 307 个归因案例，包括 125 个功能失败和 182 个效率退化案例。[2]

其发现是，问题并不只来自明显不相关的 skill。看似适用的说明，也可能诱导 Agent 错误实现或遗漏任务要求；验证清单和构建流程则可能被执行成无条件的额外工作。在所分析的案例中，过度验证和繁重实施流程是重要的效率退化来源。

这些数字描述的是研究选取并归因的失败案例，不代表所有 skill 的失败比例。它们说明了需要检查的机制：一条流程要求是否有必要，取决于任务条件和实际执行，不能仅凭其表面上的完整性判断。

## 2. 主要改进路线

### 2.1 结构化精简与按需加载

SkillReducer 将优化分为路由和正文两部分。路由层处理用于选择 skill 的描述，利用对抗性测试和 delta debugging 缩减内容；正文层按用途分类，将核心规则与辅助材料分开，并通过忠实性检查、任务评测和反馈恢复修正错误精简。[1]

论文报告，在 600 份 skill 及 SkillsBench 的评测中，描述平均压缩 48%，正文平均压缩 39%，功能质量指标提高 2.8%。这些是论文定义的压缩与质量指标，不等同于任务成功率提高 2.8 个百分点，更不等同于费用降低相同比例。

这一方法的意义在于改变信息的供给方式：核心规则保持易于访问，低频细节按需读取。它同时暴露了分层的风险。论文观察到，一类反复出现的退化来自“示例即规范”：示例迁出后，模型没有获得其中隐含的要求。恢复相应示例或明确规则，是修复这种退化的方式。

因此，分层需要验证内容能否在需要时被正确加载。主文件变短只是结构变化，任务结果和实际读取情况才说明这种变化是否有效。

### 2.2 提取共用结构

SkillZip 面向另一种膨胀：持续积累成功流程与失败补丁后，同一要求被写进多个分支、示例和警告，相同操作序列被重复展开。[3]

其方法是将重复规则放在共同适用的位置，将相同动作提取为共享过程，并将差异保留为显式例外。论文以带类型的最小描述长度目标组织压缩，对提取出的触发条件、流程关系、工具要求和输出字段设置覆盖约束。

与依赖任务试跑来筛选候选的方法不同，SkillZip 的压缩过程无需执行评测任务。这有利于降低压缩阶段的开销，也提醒人们：罕见规则不能因为未被当前测试触及就被删除。不过，结构覆盖依赖抽取结果的正确性，不能直接等同于真实执行中的行为等价。

### 2.3 保留能减少试错的操作信息

Xing 等将 skill 重写视为质量与成本的权衡，而不仅是文本压缩。[4] 一些篇幅很小的信息，例如 API 签名、参数边界、代码片段和验证命令，能够避免后续大量探索、调试和恢复。这些信息可称为操作锚点，即帮助 Agent 正确执行的具体依据。

研究比较了 API 与代码、流程约束、规则与公式等不同信息保留策略，发现不同任务族受益于不同策略，没有一个通用模板占优。其学习得到的策略在主要留出评测中，将总成本降低 7.0%；在冻结策略的跨模型迁移中，平均降低 14.7%，同时保持验证器衡量的质量。

这些结果支持根据任务性质选择保留内容，而不是按统一比例压缩所有 skill。成本下降来自信息选择与下游行为共同变化，不能仅归因于输入变短；论文中的收益幅度也不能直接迁移为其他任务的预期值。

### 2.4 根据执行反馈修订

SkillRevise 主要研究初始 skill 不完善、缺少历史轨迹的冷启动场景。[5] 它执行当前版本，从失败证据中诊断缺陷和需要保留的行为，结合修复原则生成候选，再次执行后按测得的效用保留最佳版本。最后生成的版本不一定被采用。

在论文的 GPT-5.5、SkillsBench 设置中，无 skill 的成功率为 36.05%，一次性生成 skill 为 39.53%，三轮修订预算内的结果达到 61.63%。因此，这项结果支持“执行反馈可以改善初始生成的 skill”，不能表述为对任意人工维护的成熟 skill 都有相同幅度的提升。

还应区分任务内修订和独立泛化。SkillRevise 的核心修订过程会在同一任务上重新执行候选，论文另有迁移评测。修订任务上的提升，本身不足以说明同一个候选对未见任务也有效。

GEPA 提供了更通用的反馈优化方法：读取推理、工具调用和输出等轨迹，用自然语言反思提出修改，并从不同用例上各有所长的候选中选择或组合经验。[6] 它是通用提示优化研究，为 skill 自动搜索提供方法参考；其论文并未直接证明 skill 长度与费用能同步优化。将它用于 skill 时，仍需另行定义质量目标、长度限制和费用口径。

## 3. 为什么缩短与重写会得到不同结果

Xu 与 Wu 在 40 个 SkillsBench 任务上比较了原版、保留原句的程序删减、模型重写和部分加载等条件，并在大小两个模型上每任务重复运行三次。[7] 起点是已经过整理的 skill；重写模型只能看到原文、固定指令和 token 预算，看不到任务或执行轨迹。

实验中，skill 最多缩短 54%，但任务费用没有随之下降。保留原句的删减维持了与原版相当的成功率；小模型上，原版的成功率为 42.5%，不同模型重写条件的观测结果为 29.2%～37.5%。需要注意，多重比较校正后，只有执行模型变化的效应仍显著。因此，重写的下降结果值得关注，但不足以得出“模型重写普遍有害”的结论。

这一研究与 SkillReducer、SkillRevise 的结果并不构成直接矛盾，它们的研究条件不同。

| 研究 | 修改对象与方式 | 反馈及衡量重点 |
| --- | --- | --- |
| SkillReducer | 路由描述、正文结构和辅助材料 | 忠实性检查、任务反馈、压缩与质量 |
| SkillZip | 反复积累的重复规则与流程 | 抽取结构的覆盖约束，无压缩期任务试跑 |
| Xing 等 | 不同类型的操作信息 | 固定任务条件下的质量与运行成本 |
| SkillRevise | 初始生成、尚不完善的 skill | 任务执行反馈、修订效用及迁移表现 |
| GEPA | 通用系统提示及其组成部分 | 轨迹反思与候选搜索效果 |
| Xu 与 Wu | 已整理的 skill，单次删减或重写 | 无执行反馈的缩短、任务成功率和计价成本 |

综合来看，需要区分两类活动：凭文本判断生成一个更短版本，以及通过执行结果持续修订一个候选。前者可能丢失未被识别的重要信息；后者能够利用反馈纠正错误，但需要付出额外评测成本，并防止只适应已见任务。保守删减与反馈重写各有适用条件，现有结果不足以支持唯一固定的顺序。

## 4. 长度节省为何不等于成本节省

Xu 与 Wu 的实验中，95.0% 的输入 token 按缓存费率计价。其费用由记录的未缓存输入、缓存输入和输出 token，按供应商公开费率计算，范围是任务求解阶段；生成重写版本的一次性费用另行报告。[7] 这不是包含所有基础设施、开发和评测费用的完整账单。

缓存会降低重复指令的边际成本，而工具输出、推理和多轮尝试可能占据更大的消耗。删去关键操作信息后，少量输入节省可能被额外探索抵消。反过来，保留一段正确的调用示例，也可能因为减少重试而更经济。这与 Xing 等关于操作锚点的分析一致。[4]

因此，至少应分开理解三个量：

- **内容长度**：主文件、完整包和实际加载内容的大小，统计范围必须明确。
- **任务质量**：结果正确性、触发效果和必要行为；平均分不能代替关键场景检查。
- **运行消耗**：完成任务所用的输入、输出、工具调用、时间及对应费用。

减少正文、降低加载量和减少任务费用可以同时发生，但也可能只发生其中一项。只有明确衡量对象，才能比较不同方法的收益。

## 5. 综合结论

### 5.1 优化对象是有效信息与执行行为

Skill 的价值既来自知识，也来自具体工作方法和约束。模型升级后，通用说明可能失去部分价值，专用参数、工具契约与边界规则仍可能必要。是否值得保留，应在目标模型和任务条件下判断，不能仅按内容类别或篇幅决定。

知识问答与静态检查可以帮助寻找候选修改点；它们无法替代工作流执行。模型能回答一个概念问题，不代表它在实际任务中会正确使用工具或遵守必要约束。

### 5.2 删减、分层和重写应按问题选择

重复表述适合合并，低频辅助材料适合按需提供，歧义和错误流程适合根据执行证据重写。关键是保住所需信息和行为，原句并非天然不可修改，示例也并非天然可删除。

目前较一致的研究方向是结构感知与反馈驱动：理解内容承担的作用，并在修改后观察任务表现。研究并未建立“任何 skill 都应先删后改”或“使用某种格式即可保证不退化”的通用规则。

### 5.3 质量、长度与成本需要分别验证

没有 skill 与原版的比较，用于观察原版在所测环境中的收益；原版与候选的比较，用于判断修改效果。比较时需要固定模型、任务、工具与评分条件，并明确是否同时改变了附属资源。

重复运行能够观察随机波动，独立任务有助于检查泛化，二者解决不同问题。未观察到退化只能支持相应测试范围内的结论；没有覆盖的行为，以及无法区分的微小差异，仍需保留不确定性。

因此，skill 改进可以形成“分析内容与失败原因、生成候选、执行比较、保留有效版本”的闭环。最终应交付任务质量和资源变化的证据，而不是只交付一个更短的文件。
