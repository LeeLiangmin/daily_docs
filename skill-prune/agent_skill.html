给强模型瘦身 Skill：剥离过期脚手架，保留操作锚点

2026 年多项 Agent Skill 实证研究指向同一结论：针对弱模型编写的冗余 Skill 在强模型上确实可以大幅精简，但直接用大模型“总结重写”或按困惑度压缩往往让任务通过率下降 5–13 个百分点。真正可靠的范式是以目标模型评测为门禁，依次执行新颖度审计、结构化渐进披露与轨迹驱动修订。

核心结论：已有可落地的方法论与开源框架（如 SkillReducer、SkillRevise、DSPy GEPA 与 Intel 的原子新颖度矩阵），但必须把优化目标从“压缩 Skill 字数”升级为“降低端到端任务成本且通过率不退化”。

70% → 22%

前沿模型对 Skill 通用概念的先验掌握率（约 70%）与对精确参数、契约细节掌握率（约 22%）之间的落差——决定了哪些内容该删、哪些必须留（Nikolay Petrov, Intel）。

为什么旧 Skill 值得裁，但盲目重写反而更差

过去一年针对弱模型编写的 SKILL.md 通常塞满了思维链提示、格式纠错、详尽背景科普与大量 few-shot 示例。随着基座模型能力跃升，这些补偿机制正在演变为“脚手架债务（Scaffolding Debt）”：Joinloop 引用的 ICSE 2026 追踪研究显示，在 35 项近期 LLM 工程技术中，有 37%–63% 在换用新一代强模型后被单条精简 Prompt 追平甚至反超。

在 Skill 生态内部，冗余同样普遍。香港科技大学团队在 SkillReducer 中统计了 55,315 份公开 Skill，发现正文中仅有 38.5% 是可执行的核心规则，超过 60% 是背景解释（40.7%）、示例（12.9%）与模板（7.6%）。去除上下文干扰甚至会带来“少即是多（Less-is-More）”收益：在 600 份 Skill 评测中，结构化精简使正文减少 39%，平均任务得分反而提升 2.8%（官方长 Skill 上提升达 11.8 个百分点）。

然而，把 Skill 丢给大模型做一次性“精简重写”是一条被证伪的捷径。2026 年 10 月发表的对照研究 Shortening agent skills leaves LLM agent cost unchanged 在 40 个 SkillsBench 任务上按真实 API 账单计费，揭示了两个反直觉事实：第一，多轮 Agent 执行中约 95.0% 的输入 Token 命中 Prompt Caching，单靠缩短 Skill 最多 54% 并未降低实际账单；第二，无执行反馈的模型重写会让成功率显著下滑 5.0–13.3 个百分点（哪怕由更强的大模型来改写也是如此），因为重写极易抹掉防止 Agent 盲目试错的稀疏“操作锚点”，反而引发更昂贵的下游探索（Xing et al., 2026）。

目前业界并不存在“一键全自动且零风险”的单一银弹，而是形成了覆盖新颖度诊断、结构去臃肿、无评测语法压缩、轨迹驱动修订、帕累托 Prompt 进化五条技术路线的互补工具链。下表汇总了七套最具代表性的框架与实证数据。

面向强模型的四阶段 Skill 瘦身与重写方法论

综合上述研究，如果你要将一批为弱模型设计的 Skill 迁移到目标强模型，并确保内容显著精简且能力不弱于原版，最稳妥的做法是把“诊断、分层、重写、门禁”拆解为一条四阶段闭环流水线——先删“模型已知的废话”和“过期的拐杖”，再把“非核心材料”下沉为按需加载，最后只在失败处做带保留约束的局部重写。

STAGE 01 · AUDIT

先做脚手架分类与原子级新颖度体检

按 Joinloop 消融框架将 Skill 中的模块标为三类：拐杖（Crutch）（如思维链指令、自检循环、格式示例）、放大器（Amplifier）（外部检索、测试反馈、工具契约）与护栏（Guardrail）（安全与合规红线，直接豁免裁剪）。

接着借鉴 Intel Nikolay Petrov 的方法，把知识型条目拆为 25–30 个原子问答对，在目标强模型上跑“不加载 Skill vs. 加载 Skill”双臂测试（单份 Skill 成本不到 $0.5）。优先处理让强模型反而答错的“负贡献条款”，再把双臂皆对的“已知通识”列入候选删除清单。

STAGE 02 · DEBLOAT & TIER

路由层 Delta Debugging + 正文渐进式披露

参照 SkillReducer，不要把 Skill 当成扁平文本去压缩。路由描述（description）先按语义子句切分，在含混淆项与对抗性“影子 Skill”的候选池中用 ddmin 二分缩减到 1-minimal 集合，再放入真实 Agent 运行时验证触发率，缺失则贪心恢复。

正文则做五分类切片：仅将核心规则（Core Rules）与精确参数契约保留在常驻 SKILL.md 中；将示例、模板、背景说明拆分到 examples.md、templates.md 等卫星文件，并附带 when 触发条件与 3–5 个主题词，改由 Agent 通过 read_file 按需加载。若存在多份重复补丁，可用 SkillZip 的 MDL 思路合并共享流程、仅留例外差异。

STAGE 03 · ANCHORED REVISION

带“保留台账”的轨迹驱动重写与帕累托寻优

严禁无执行反馈的一次性重写。在目标强模型上运行真实评测任务，针对失败轨迹采用 SkillRevise 的三件套：失败归因（Diagnosis）、保留台账（Preserve Ledger，锁定已通过用例依赖的指令，缺失会导致 12.79pp 退化）与可执行锚点（Execution Anchors）。

重写时遵循 Xing et al. (2026) 的成本感知原则——明确保留 API 签名、字段边界、验证命令等高杠杆锚点；如需自动搜索更短表达，可接入 DSPy GEPA，以“验证通过率 × 端到端成本”为多目标维护帕累托前沿，且严格设定门控效用函数（仅在任务通过时才奖励更短的 Token，防止模型靠“偷工减料提前结束”骗取高分）。

STAGE 04 · VERIFY & SHIP

目标模型多轮回归门禁与解耦发布

精简版必须过三道门禁才允许合入：第一，重复稳定性——每条用例至少跑 3 次，确认得分变化落在方差之上而非随机波动；第二，切片防退化——按任务域、难度、长短输入拆切片检查，防止平均分持平掩盖 8% 关键长尾场景崩坏；第三，真实账单核验——对比含 Prompt Caching 折扣后的端到端美元成本（Skill + 下游探索 + 输出推理 Token）。

任何单条用例退化时，参考 SkillReducer Gate 2 机制将对应缺失的示例或规则原样回升（Promote）至常驻核心（最多 2 轮即可恢复约 81.6% 的失败案例）。上线时务必将“切换强模型”与“发布瘦身版 Skill”拆为两次独立发布，避免归因混杂。

判断每一条 Skill 指令“该删、该下沉还是该留”的决策矩阵

将 Petrov 的四象限新颖度测试与 Joinloop 的脚手架三分类合并，即可得到一张可直接用于逐行审查 SKILL.md 的工程判定表。

落地前必须避开的五个工程陷阱

即便理解了方法论，团队在实际改造旧 Skill 时仍容易踩进评估失真与过度工程化的坑。Xu & Wu (2026) 在 SkillsBench 上的实证数据非常直观地展示了不同裁剪手法在成功率上的巨大分叉。

1. 把“Skill 变短”等同于“运行更省钱”

由于静态 Skill 位于对话前缀且缓存命中率高达 95%，删掉 1,500 个缓存 Token 省下的钱微乎其微；一旦误删关键提示导致 Agent 多走 2 轮工具调用，总账单反而上升（Xu & Wu, 2026）。优化指标必须是单次成功任务的端到端总费用与时延。

2. 误删“隐式规范型示例（Example-as-Specification）”

SkillReducer 指出，在全部 600 份 Skill 中真正的压缩退化仅占 4.7%，而其头号成因正是作者把未明文写出的输出格式或边界规则隐含在示例里——示例被迁出后规则随之丢失。因此必须保留“失败示例原样回升”的自动反馈机制。

3. 迷信“结构化 Schema 重写”

很多人喜欢把散文式 Skill 重写成带优先级、字段标签的 JSON/YAML 结构。实证表明，在指令单元完全相同的前提下，结构化重写比纯文本重写低 8.3 个百分点（29.2% vs. 37.5%，Xu & Wu, 2026），在大模型上也仍有 8.4 个百分点落差。优先采用保留原句的删减与分层，而非强行套壳改写。

4. 用旧模型时代的评测集评估新模型

为弱模型积累的测试集往往过度聚焦旧模型的低级失误，却缺少新模型在复杂自主规划中暴露的新失败模式。在启动消融之前，应先从近期生产日志中补充真实难例，并在每个模型大版本更新时周期性复跑（Joinloop, 2026）。

5. 升级模型与瘦身 Skill 捆绑上线

如果同时替换基座模型和裁剪 Skill，线上出现质量波动时无法判断是模型差异还是删减过头。工程上应先以原版 Skill 切换至目标强模型并验证稳定，再在独立版本中灰度发布精简后的 Skill。

本周即可跑通的最小可行落地路线

不必从零复现整套论文系统，建议按 Skill 库规模分两步渐进落地：先用低成本诊断拿到 80% 收益，再把高频或高价值 Skill 接入自动化修订闭环。

  1. 建立最小基准集（1 天）：为每个待瘦身 Skill 准备 5–10 条覆盖核心路径与边缘约束的真实任务用例（优先带确定性脚本/断言验证），直接用 Anthropic skill-creator 跑出目标强模型“无 Skill”与“原版 Skill”的双基线。
  2. 跑一次原子新颖度体检（半天，成本极低）：写一段约 80 行脚本，将 SKILL.md 拆为 25–30 个原子问答项并在目标模型上跑双臂测试，由跨家族模型打分，立刻筛出“负贡献条款”与“双臂全对的已知通识”（Petrov 方法）。
  3. 执行保守删减与渐进式分层（1 天）：优先做保留原句的删减（移除已确认冗余的拐杖与通识），并参照 SkillReducer 将大段示例、背景、模板拆入 references/ 子文件并写清 when 触发条件。
  4. 接入自动重写与回归门禁（进阶自动化）：若存量 Skill 达数十至上百份，可引入 DSPy GEPA（设定“通过率不降 + 总 Token 最小”的帕累托指标）或复现 SkillRevise 的 Diagnosis + Preserve Ledger 3 轮修订循环，把 Skill 瘦身纳入模型升级时的标准 CI 流水线。
强模型时代的 Skill 工程不再是“把文档写得越短越好”，而是把通用教学删干净，把模型永远猜不到的精确契约与操作锚点留下来。 综合自 SkillReducer、SkillRevise、Xing et al. (2026) 与 Intel 原子新颖度研究的核心共识
