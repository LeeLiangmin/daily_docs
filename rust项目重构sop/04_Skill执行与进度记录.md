# Skill 执行与进度记录

## 1. 基本原则

迁移进度严格按照迁移 skill 的执行顺序和 skill 自己的内部阶段记录。

项目流程不重新定义一套“分析、翻译、测试”等迁移阶段。

项目层只负责知道：

- 当前执行到哪个 skill；
- 当前 skill 执行到哪个阶段；
- 当前阶段完成了什么；
- 当前还缺什么；
- 有没有阻塞；
- 是否可以进入下一个 skill。

---

# 2. Skill 执行顺序

```text
legacy-spec
```

# 6. Skill 切换确认

当前 skill 完成后，进入下一个 skill 前确认：

- [ ] 当前 skill 已按自身要求执行完成
- [ ] 必要产出已经生成
- [ ] 当前结果没有阻塞后续的问题
- [ ] 重要问题已经记录
- [ ] 下一个 skill 所需要的输入已经准备好

执行逻辑：

```text
当前 skill
    ↓
完成确认
    ↓
结果作为输入
    ↓
下一个 skill
```

# 8. 阻塞问题

普通技术问题按 skill 自身流程处理。

只有会影响项目继续推进的问题，才在这里记录。

例如：

- 当前 skill 无法继续；
- 上一个 skill 的产出不足；
- 原代码行为无法确认；
- 需要业务方提供额外信息；
- 编译或测试环境存在问题；
- 项目方案需要调整；
- 问题会影响后续多个 skill。

# 10. 项目进度怎么看

不强调一个抽象的完成百分比。

优先使用这种方式：

```text
legacy-spec       已完成
legacy-ffi        已完成
legacy-test-gen   进行中：<当前阶段>
legacy-translate  未开始
legacy-lite-tdd   未开始
```

这样可以直接看出当前迁移到了哪里。
