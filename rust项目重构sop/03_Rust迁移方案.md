# Rust 迁移方案

## 1. 基本原则

本方案只针对当前这一个 C/C++ 项目。

执行期间：

- 一次只迁移一个 C/C++ 项目；
- 当前项目使用一个确定的模型；
- 项目流程不重复定义各 skill 内部如何迁移代码；
- 具体迁移执行由现有 skill 负责；
- 项目层只负责确定范围、约束、输入、风险和是否具备开始迁移的条件。

主要处理方式：

- 改成 Rust；
- 保留原 C/C++；
- Rust 与 C/C++ 混合；

# 11. 迁移 Skill 顺序

当前项目按照以下顺序执行：

```text
legacy-spec
    ↓
legacy-ffi
    ↓
legacy-test-gen
    ↓
legacy-translate
    ↓
legacy-lite-tdd
```

每个 skill 使用其自身定义的阶段。

本方案不重新定义 skill 内部步骤。

如果某个项目确实不需要执行某个 skill，需要明确说明原因。

---

# 12. 迁移完成后需要得到什么

当前项目迁移结束后，至少应得到：

- Rust 实现代码；
- 必要的测试代码；
- 项目能够正常构建；
- 目标平台能够正常构建；
- 迁移范围内功能完成；
- 项目能够正常集成运行；
- 重要遗留问题有记录；
- 所有必需 skill 已完成。
